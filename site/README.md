# plainphone.org

The Plainphone website is available in English (`/`), Danish (`/da/`), Swedish
(`/sv/`), Norwegian Bokmål (`/nb/`) and German (`/de/`). Each language has a home
page, setup guide, privacy policy, help pages, app and website lookup, and page
about the research behind Plainphone.
The language menu keeps readers on the equivalent page. The build adds canonical
URLs, hreflang tags, sitemap alternates, Open Graph and Twitter metadata,
and a localized share image for each language. The landing pages include
Organization, SoftwareApplication and FAQPage structured data. The documentation
pages include breadcrumbs in their structured data. The FAQ markup is generated
from the same questions and answers users can open on the page. Assign a stable
FAQ group key when adding a question, independent of its position in the file.

The dependency-free build produces plain HTML and CSS. A small, integrity-pinned
module filters the app and website lookup locally. The full catalog stays readable
with JavaScript disabled. No cookies, analytics, tracking or third-party requests.

## Build and check

```sh
cd site
npm run build          # writes dist/
npm run check          # search tests, links, language counterparts and CSP
npm run check:external # also fetches external links
```

Preview with any static server, e.g. `python3 -m http.server -d dist 4321`.

| `content/home.mjs` | Front page copy for the switch design in all five languages: the alt text and captions of the screenshots, what is always on and what you choose, who decides, what the child sees, the two setup modes and the closing call to action. `panel` is no longer shown on the page; `tools/make-images.mjs` still uses it for the share images |
| `src/img/` | The real screenshots on the front page (WebP, 1x and 2x, light and dark, five languages) and `manifest.json` with their sizes. Generated by `pnpm site:screenshots`, see below. Never edit by hand |

| `figures.mjs` | The schematic phone drawings in the guide: inline SVG, coloured by the page's own custom properties |
| `src/style.css` | The only stylesheet. It is inlined into each page and pinned by a CSP hash. |
| `src/brand/` | Copies of the direction C files from [`docs/brand/directions/c/`](../docs/brand/directions/c/): the outlined wordmark, the mark, the favicon and the app icon (only the files the build and `tools/make-images.mjs` read). Change them there first. The header draws the mark inline so dark mode can use the dark drawing |
| `src/og-*.png`, `src/*icon*.png` | Share images and icons, generated by `tools/make-images.mjs` |
| `src/fonts/` | Schibsted Grotesk 400–700 (variable) and IBM Plex Mono 500, both SIL OFL 1.1 (`OFL.txt`), self-hosted Latin subsets (U+0000–00FF and general punctuation, so æøå, äöüß, en dash and quotes) |

The files in `tools/` are dev-only and need `playwright` (and `axe-core` for the QA
script) from a directory you pass with `NODE_PATH`. Their output is committed. Run them from `site/`:

| Script | When |
|---|---|
| `tools/make-images.mjs` | The hero copy, the hero panel or the brand files change. Writes `src/og-*.png`, `favicon-32.png` and `apple-touch-icon.png` |
| `tools/qa.mjs` | Before a pull request that changes layout or copy. Builds nothing; run `npm run build` first. Checks every page in every language at 320, 390, 768 and 1280 px in light and dark mode: no horizontal scrolling, axe-core WCAG 2.2 AA, the menus without JavaScript and keyboard focus |
| `tools/site-screenshots.mjs` | The dashboard or the phone UI changes (or a string the pictures show). Run `pnpm site:screenshots` in the repo root; see Screenshots below |
| `tools/screenshots.mjs` | Full-page screenshots of `/` and `/da/` at 390 and 1280 px, light and dark |

```sh
NODE_PATH=<directory containing playwright and axe-core> node tools/qa.mjs
```

## Screenshots

The front page shows real screens, not drawings: the parent dashboard (hero) and a request from the phone
(who decides), and the child's home screen in school time, the stop screen and "What can my parents see?".
Everything is a fictional child called Sam with fixed dates (19 November 2026), never real people or today's date.

```sh
pnpm site:screenshots   # from the repo root; commit site/src/img/
```

- The phone pictures come from the Robolectric test `SiteScreenshotTest` (`android/`), which writes
  PNGs to `android/app/build/site-screenshots/` with the real strings of each language, light and dark.
- The dashboard pictures come from `web/screenshots/site.html`, which renders the real dashboard components
  with fixtures on the Vite dev server (no network), shot with Playwright (`NODE_PATH` or `PLAYWRIGHT_NODE_PATH`).
- ImageMagick converts everything to WebP at 1x and 2x. `--skip-android` and `--skip-web` redo only one half.
- `build.mjs` writes a `<picture>` with a dark source, `srcset`, width and height from `manifest.json`, and the
  alt text from `content/home.mjs`. The hero picture loads first, the others lazily.
- `npm run check` fails if any picture is missing for a language, is not a WebP, does not match the size in the
  HTML or has no alt text. Change the UI, run the script, commit the new files in the same pull request.

## Design notes

The site uses brand direction C, "Switch", from the [brand guide](../docs/brand/README.md):
graphite and white, Schibsted Grotesk and IBM Plex Mono, 6 px surfaces with a 1.5 px
edge, pill-shaped buttons and no shadows. Signal green (`--brand`, `#c5f04a`) means
"on" and nothing else: switch fills and the mark. It is never decoration and never a
call button. In dark mode it is also the action colour, as the guide says. A switch
always shows its state by position as well as colour, and screen readers hear the word.

The front page is organised around the switch. The hero makes one promise and shows an
example list of switches. Then: what is always on (112 and the parents) and what you
choose, who decides, what the child sees on the phone, a child's phone versus your own,
strong versus light mode, the first day, the project's status, free and open source with
self-hosting, privacy, questions and a calm closing call to action. The copy keeps
saying who decides and that the child can see it, because a switch on its own can read
as control. See the [design principles](../docs/design-principles.md) for the rationale.
Before and after screenshots are in [`docs/screenshots/site-redesign-switch/`](../docs/screenshots/site-redesign-switch/).
Before and after screenshots of the real-screenshot change are in [`docs/screenshots/site-real-screenshots/`](../docs/screenshots/site-real-screenshots/).

The Danish copy covers Android parental controls, a child's first phone and
keeping essential apps such as Aula. The English copy covers those first-phone
and app-limit questions and the idea of using an Android as a dumbphone. These
are search intents inferred from public help and parent guidance, without
search-volume estimates. See [Google for Families](https://support.google.com/families/answer/9499456?hl=da),
the [City of Copenhagen’s first-phone guidance](https://skaermvaner.kk.dk/skaerm-og-alder/6-12-aar/telefon-eller-ej),
the [Danish Health Authority](https://www.sst.dk/vidensbase/forebyggelse/anbefalinger-om-brug-af-skaerm/skaermbrug-i-fritiden-saadan-kan-du-goere)
the [FTC guide to kids and cell phones](https://consumer.ftc.gov/articles/kids-cell-phones)
and [Intent Phone’s FAQ on keeping essential apps](https://intentphone.com/faq.html).

## Security headers

Cloudflare Pages serves the generated `_headers` file. The CSP allows a SHA-256
hash for the inline stylesheet and a separate hash for the search module, whose
script tag also carries a matching integrity attribute. The policy restricts
fetches to the site's own origin and blocks framing. JSON-LD is inert metadata.
The check script requires the stylesheet on every page, verifies both hashes
and rejects off-origin resource URLs.
The `/mail/` assets keep cross-origin embedding enabled for sign-in emails.
After deployment, verify the response headers and the plain-text security contact
on the production hostname. Renew the `security.txt` expiry in `build.mjs`
before 18 November 2027.

## Deploy

The site is a Cloudflare Pages project called `plainphone`, served at
plainphone.org. `www.plainphone.org`, `plainphone.dk` and `plainphone.eu`
redirect to it with a 301.

**Automatic.** A push to `main` that touches `site/` or the country catalog runs
[`.github/workflows/site-deploy.yml`](../.github/workflows/site-deploy.yml): build, run
`npm run check`, then `wrangler pages deploy`. The website is built and checked in pull requests by
the [site job in `ci.yml`](../.github/workflows/ci.yml). You can also start the deploy workflow from the Actions
tab (`workflow_dispatch`), but only on `main`, and it only runs in the
`plainphone/plainphone` repository, so forks do not try to deploy.

The repository needs two Actions secrets (names only, values live in Cloudflare):

| Secret | What |
|---|---|
| `CLOUDFLARE_API_TOKEN` | A token that may edit Cloudflare Pages on the account, nothing else |
| `CLOUDFLARE_ACCOUNT_ID` | The account that owns the `plainphone` project |

Wrangler is pinned in the workflow (`wrangler@4.x.y`). Raise it on purpose, in a pull request.

**By hand**, if Actions is unavailable:

```sh
cd site && npm run build && npm run check
CLOUDFLARE_API_TOKEN=... CLOUDFLARE_ACCOUNT_ID=... \
  npx wrangler@4.163.0 pages deploy dist --project-name plainphone --branch main
```

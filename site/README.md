# plainphone.org

The landing page for Plainphone, in English (`/`) and Danish (`/da/`).

It is plain HTML and CSS, built by one Node script with no dependencies and no
client-side JavaScript. No cookies, no analytics, no external fonts or requests.

## Build and check

```sh
cd site
node build.mjs                    # writes dist/
node scripts/check.mjs            # pages, internal links, anchors, no scripts, no third-party loads
node scripts/check.mjs --external # also fetches external links
```

Preview with any static server, e.g. `python3 -m http.server -d dist 4321`.

## Where things are

| Path | What |
|---|---|
| `content/en.mjs`, `content/da.mjs` | All copy. Change text here, keep the two languages in step. |
| `why` in the same files | The research and design page (`/why/`, `/da/hvorfor/`). See the [evidence review](../docs/evidence.md) for source checks and limitations. |
| `privacy` in the same files | The privacy policy (`/privacy/`, `/da/privacy/`). Change it in the same pull request as anything that changes what the server stores, and update the date in `updated`. The technical basis is [`docs/privacy.md`](../docs/privacy.md) |
| `setup` in the same files | The setup guide (`/setup/`, `/da/setup/`). The dashboard links to exactly these two addresses, so they must keep existing. Change the steps in the same pull request as anything in the dashboard's Add phone flow or the setup QR code |
| `figures.mjs` | The schematic phone drawings in the guide: inline SVG, coloured by the page's own custom properties |
| `src/style.css` | The only stylesheet. It is inlined into each page and pinned by a CSP hash. |
| `src/wordmark.svg`, `src/favicon.svg` | Logo and mark, generated by `tools/make-wordmark.py` |
| `src/og-*.png`, `src/*icon*.png` | Share images and icons, generated by `tools/make-images.mjs` |
| `src/fonts/` | Atkinson Hyperlegible Next (SIL OFL 1.1), self-hosted, Latin subset |
| `build.mjs` | Builds pages, 404, sitemap, robots.txt and the Cloudflare `_headers` file |

The files in `tools/` are only needed when the logo or images change. They need
`fonttools` + `brotli` and `Pillow` (Python) and `playwright` (Node); their output is committed.

## Design notes

Plainphone is the opposite of a screen trap, so the page is quiet: one typeface,
cool paper and blue-black ink, one highlighter color for the honest status line,
and no motion. The one memorable element is the ledger in the hero: what stays,
and what is crossed out. Light and dark mode follow the system setting. All text
meets WCAG AA (most of it AAA).

## Deploy

The site is a Cloudflare Pages project called `plainphone`, served at
plainphone.org. `www.plainphone.org`, `plainphone.dk` and `plainphone.eu`
redirect to it with a 301.

**Automatic.** A push to `main` that touches `site/` runs
[`.github/workflows/site-deploy.yml`](../.github/workflows/site-deploy.yml): build, run
`scripts/check.mjs`, then `wrangler pages deploy`. Pull requests are built and checked by
`site.yml` but never deployed. The workflow can also be started by hand from the Actions
tab (`workflow_dispatch`), but only on `main`, and it only runs in the
`plainphone/plainphone` repository, so forks do not try to deploy.

The repository needs two Actions secrets (names only, values live in Cloudflare):

| Secret | What |
|---|---|
| `CLOUDFLARE_API_TOKEN` | A token that may edit Cloudflare Pages on the account, nothing else |
| `CLOUDFLARE_ACCOUNT_ID` | The account that owns the `plainphone` project |

Wrangler is pinned in the workflow (`wrangler@4.x.y`). Raise it on purpose, in a pull request.

**By hand**, if Actions is unavailable:

```sh
cd site && node build.mjs && node scripts/check.mjs
CLOUDFLARE_API_TOKEN=... CLOUDFLARE_ACCOUNT_ID=... \
  npx wrangler@4.163.0 pages deploy dist --project-name plainphone --branch main
```

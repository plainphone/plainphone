# Plainphone parent app

Choose each phone’s Plainphone language in its management settings. To set up
a new or reset phone, choose strong mode and a language in the app, then continue
in the browser to create the setup QR code. The app is available in English,
Danish, Swedish, Norwegian Bokmål and German. See [translation review status](../docs/translations.md).

The native parent app for iOS and Android. It does the same as the parent web app in [`../web`](../web), on the same API ([`../server/openapi.yaml`](../server/openapi.yaml)):

- log in with a link from your mail (the link opens the app)
- phones: add one by scanning its QR code or typing its code, rename, remove
- apps, approved contacts, web filter, school time, bedtime and daily screen time (one cap for all apps, caps for single apps, weekday overrides, 15 extra minutes today)
- the phone's last position on a map, with Find, "Drive there", ringing the phone, "Are you okay?" and when the phone may send its position
- the Self profile's key, changes waiting for the key, and approvals for a trusted person
- household: other parents and invitations
- live updates while the app is open: an SOS, requests, positions and inbox messages show at once ([docs/live-updates.md](../docs/live-updates.md))

English and Danish, light and dark mode, screen readers and large text. No analytics, crash reporting or other tracking SDKs.

On iPhone the same app will also be the child's app (docs/ios/architecture.md, phase 1). An iOS
build made with `PLAINPHONE_IOS_CHILD=1` asks "Whose phone is this?" on the first launch of an
iPhone with iOS 26 or later (older iPhones get the parent app only) and, for a
child's iPhone, runs a guided setup (Screen Time permission, pairing by QR code, Apple's own
settings) and then syncs the rules through the Swift module in
[`modules/plainphone-screentime`](modules/plainphone-screentime). Other builds are Parent only.
The Swift code is built and tested from [`../ios`](../ios).

Stack: Expo SDK 58, Expo Router, React Native 0.88, TypeScript. The iOS bundle ID is `org.plainphone.app`. The Android parent package is `org.plainphone.parent`. See the [parent app guide](../docs/parent-app.md) for build overrides.

## Develop

```sh
cd parent-app
pnpm install          # installs the root workspace; the app shares code with web/ through packages/
pnpm web              # quickest look, in a browser
pnpm android          # needs the Android SDK; builds and starts on a device or emulator
pnpm ios              # needs a Mac with Xcode
```

The app is part of the root pnpm workspace with pnpm's default (isolated) `node_modules`, which Expo supports since SDK 54. Expo's Metro config finds the workspace by itself, so there is no `metro.config.js`; the packages in [`../packages`](../packages) are TypeScript source that Metro, Jest and `tsc` compile with the app.

The app talks to `https://app.plainphone.org` by default. Select **Use your own server** at sign-in to connect to a different server (see [docs/parent-app.md](../docs/parent-app.md)).

## Checks

| Command | What it checks |
|---|---|
| `pnpm typecheck` | TypeScript |
| `pnpm lint` | ESLint (eslint-config-expo) |
| `pnpm test` | Jest + React Native Testing Library: login, the login link, phones, settings, links, push routing, copy |
| `pnpm export` | bundles iOS, Android and web |

CI runs all of them in the `parent-app` job of [`.github/workflows/ci.yml`](../.github/workflows/ci.yml). The server job checks that the generated API types match `server/openapi.yaml` (`pnpm --filter @plainphone/api-client check`).

## Layout

- `src/app/`: screens (Expo Router; every file is a route)
- `src/api/`: the typed client (`client.ts`) and domain types. Paths, parameters and request bodies are checked against `openapi.yaml` through the types in [`@plainphone/api-client`](../packages/api-client); most responses are not described there yet, so their types are hand-written in `models.ts`
- `src/components/`: building blocks (`ui.tsx`), the phone context, the map
- `src/i18n/`: language handling and the app-only copy; the copy shared with the PWA is in [`@plainphone/i18n`](../packages/i18n)
- `src/lib/`: session, links, notifications, storage, theme

Formatting, phone state, approvals, change descriptions and the other logic the PWA shows the same way come from [`@plainphone/shared`](../packages/shared).

`android/` and `ios/` are generated by `npx expo prebuild` and not committed.

Enable SOS notifications from Settings. Active alerts appear above the phone list and SOS history is on each Child phone's overview. [SOS setup](../docs/sos.md).

Building for the stores, app links and push: [docs/parent-app.md](../docs/parent-app.md).
